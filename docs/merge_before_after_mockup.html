1. 확정된 요구사항

#항목확정 내용
1사용 가능한 기타 목적Layer 추가/삭제 · STEPSEQ 변경 · Overlay 변경 3개에서 참조 요청서 Merge 사용
2중복 노출 방지3개 중 2개 이상을 골라도 Merge 블록은 1개만 표시 (참조 요청서도 1건)
3표시 항목process_id / sp / sd / pp / layerid(= 표의 col_layer) 5개 + 맨 앞 J-ayer/O-ayer 배지
4같은 줄 판정process_id + layerid 가 같고 sp/sd/pp 중 하나라도 다르면 같은 줄(A→BEFORE, B→AFTER). 5개 모두 같으면 변경 없음 으로 표에서 제외
5한쪽에만 있을 때대칭 처리 — B 에만 있으면 BEFORE=미등록, A 에만 있으면 AFTER=미등록
61:1 이 아닐 때같은 process_id+layerid 그룹에 A·B 행이 여러 개면 자동 매칭하지 않고 BB 매핑처럼 사용자가 직접 짝을 지어 적용
7표 구성표 2개 — ① BEFORE/AFTER 표(미확정, 각각 미등록 항목 포함) ② 변경전/변경후 표(확정된 짝)
8수정 가능 범위자동으로 맺어진 짝이 틀렸으면 해제 후 다시 매핑 가능 (셀 값 직접 편집은 범위 밖)
9기존 3-way Merge현행 유지 — Merge 확정 시 J/O 표의 st/new_or_copy 재판정(신규·기등록·layer삭제)은 지금 그대로 동작. BEFORE/AFTER·변경전/변경후 표는 결과를 보여주는 별도 화면
10저장·노출확정된 변경전/변경후 결과를 문서에 저장 → 의뢰 상세 페이지(결재/이력)에도 표시

2. 동작 흐름

① 기타 목적 선택Layer 추가/삭제 · STEPSEQ 변경 · Overlay 변경 중 1개 이상 → Merge 블록 1개 노출
② 참조 요청서 선택결재완료 문서 검색 → J/O 행 로드
③ Merge 실행확인 모달 → 기존 3-way 재판정 그대로 J/O 표에 반영 + 비교 결과 생성
④ 자동 판정1:1 성립 → 변경전/변경후 표
모호 → BEFORE/AFTER 표
⑤ 수동 매핑BEFORE 1행 + AFTER 1행(또는 미등록) 선택 → 매핑 → 적용
⑥ 저장상신·임시저장 시 함께 저장 → 상세 페이지 노출

자동 매칭 규칙 (같은 process_id + layerid 그룹 단위)

그룹 안의 A 행 수B 행 수처리가는 곳
11값이 모두 같으면 제외, 하나라도 다르면 자동 1:1변경전/변경후 표
N (≥1)0각 행을 AFTER=미등록 과 자동 짝 (모호성 없음)변경전/변경후 표
0N (≥1)각 행을 BEFORE=미등록 과 자동 짝 (모호성 없음)변경전/변경후 표
둘 다 ≥1 이고 한쪽이라도 ≥2자동 매칭하지 않음 — 사용자가 직접 매핑BEFORE/AFTER 표

비교 대상: J-ayer 는 J-ayer 끼리, O-ayer 는 O-ayer 끼리만. 비활성(disabled) 행과 layerid 가 빈 행은 비교에서 제외합니다.

5. 검증 계획

자동 테스트

  • computeBeforeAfter — ① 5개 값 완전 일치 → 결과 제외 ② sp만 다름 → 자동 changed ③ A만 존재 → deleted(AFTER 미등록) ④ B만 존재 → added(BEFORE 미등록) ⑤ 같은 키 A2:B2 → 자동 매칭 없이 미매칭으로 분류 ⑥ A3:B0 → 3건 자동 deleted ⑦ layerid 빈 행 제외 ⑧ 비활성 행 제외 ⑨ J/O 독립 ⑩ 공백 trim 정규화 ⑪ 멱등성
  • 실행: cd frontend && npm test -- --watchAll=false --passWithNoTests

수동 검증 시나리오 (규칙 C-2-1)

시나리오조작 순서성공 판정
① 노출 조건 의뢰서 작성 → 라인·조합법·제품·조리법 입력 → 요청 목적 신규 → 기타 목적에서 STEPSEQ 변경 클릭 → 이어서 Layer 추가/삭제·Overlay 변경 도 클릭 참조 요청서 입력칸+Merge 버튼이 1개만 표시. 3개를 모두 해제하면 블록이 사라지고 선택값 초기화
② 자동 매칭 참조 요청서 선택 → Merge → 확인 모달 승인 기존처럼 J/O 표가 재판정되고, 아래에 요약 바 + BEFORE/AFTER 표 + 변경전/변경후 표가 나타남. 5개 값이 모두 같은 행은 어느 표에도 안 나옴
③ 수동 매핑 BEFORE 에서 1행 클릭 → AFTER 에서 1행 클릭 → 매핑 추가 → 적용 두 행이 BEFORE/AFTER 표에서 사라지고 변경전/변경후 표에 한 줄로 추가됨. 확정 열이 수동
④ 미등록 매핑 BEFORE 에서 미등록 행 클릭 → AFTER 에서 아무 행 클릭 → 매핑 추가 → 적용 변경전 칸이 미등록(회색 이탤릭)으로, 판정이 추가로 표시됨
⑤ 짝 재지정 변경전/변경후 표에서 자동 확정 행의 ✕ 클릭 해당 행이 사라지고 BEFORE/AFTER 표에 두 행이 되살아남 → 다시 매핑 가능
⑥ 저장·재진입 임시저장 → 목록에서 다시 열기 변경전/변경후 표 내용이 그대로 복원됨
⑦ 상세 노출 상신 → 결재 현황에서 해당 의뢰서 행 클릭 → 상세 1페이지 스크롤 "변경전/변경후" 카드가 보이고 J/O 배지·5개 항목이 작성 화면과 동일하게 표시. 실패 신호: 카드가 비어 있거나 미등록이 - 로만 보임
⑧ 회귀 기타 목적을 공법 추가/변경 만 선택 참조 요청서 블록이 나타나지 않음 (기존 동작 유지). 완성된 MAP 변경 단독 전용 동작도 그대로

잠재 이슈 · 주의사항

  • 조리법 변경 시 초기화 — process_id 가 바뀌면 J/O 가 재조회되어 참조 상태가 초기화됩니다(index.tsx:507-510). 새로 만든 merge_pairs 도 같이 비워야 유령 데이터가 남지 않습니다.
  • Merge 후 J/O 수동 편집 — 3-way 반영 후 사용자가 J/O 행을 고치면 저장된 merge_pairs 와 실제 표가 어긋날 수 있습니다. 표시 전용 스냅샷(Merge 시점 기록)으로 정의하고 상세 페이지에도 "Merge 시점 기준" 문구를 답니다.
  • 기존 매칭 키 결함 — computeLayerMerge 의 키에 layerid 가 빠져 있는 알려진 문제(docs/REQUEST.md:282)는 이번 범위에서 건드리지 않습니다(요구사항 #9 = 현행 유지). 새 computeBeforeAfter 는 process_id+layerid 를 쓰므로 두 계산의 기준이 다릅니다 — 의도된 분리입니다.
  • 구버전 문서 — merge_pairs 없는 기존 문서는 ?? [] 백필. 상세 페이지에서도 빈 배열이면 카드를 아예 숨깁니다.
  • 성능 — J/O 각 수백 행 규모에서 그룹핑은 Map 기반 O(n). 문제 없습니다.

1표 위치 STEP 1 의 참조 요청서 블록 바로 아래 인라인 (BB 매핑이 STEP 4 인라인인 것과 동일) 별도 모달로 띄우기

4참조 요청서 잠금 현행 유지 — Merge 확정 시점에 참조 요청서 영구 잠금 (요구사항 #9 "기존 유지"에 맞춤) 매핑 적용 시점으로 늦추기 / 초기화 버튼 추가
5미매핑 잔여 행 BEFORE/AFTER 에 짝 없이 남은 행이 있어도 상신 차단하지 않음(경고만) 전부 매핑해야 다음 STEP 진행 가능하도록 검증 추가
