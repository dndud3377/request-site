2. 동작 흐름

① 기타 목적 선택3개 중 1개 이상 → Merge 블록 1개 노출
② 참조 요청서 선택결재완료 문서 검색 → J/O 행 로드
③ Merge 실행확인 모달 → J/O 스냅샷 저장 → 3-way 재판정 반영 + 비교 결과 생성
④ 자동 판정1:1·한쪽만 → 변경전/변경후 표
모호 → BEFORE/AFTER 표
⑤ 수동 매핑BEFORE 1행 + AFTER 1행 선택 → 적용 즉시 확정 (반복)
⑥ 게이트AFTER 가 0행이 되어야 다음 STEP·상신 가능
⑦ 저장상신·임시저장 시 함께 저장 → 상세 페이지 노출

언제든 재선택 버튼으로 ②~⑤ 를 통째로 되돌릴 수 있습니다(③에서 저장한 스냅샷으로 J/O 표까지 복구).

① 노출 조건의뢰서 작성 → 라인·조합법·제품·조리법 입력 → 기타 목적에서 STEPSEQ 변경 → 이어서 Layer 추가/삭제·Overlay 변경 클릭참조 요청서 블록이 1개만 노출. 3개 모두 해제하면 블록·표 사라지고 상태 초기화
② 자동 매칭참조 요청서 선택 → Merge → 확인 모달 승인J/O 표가 기존처럼 재판정되고, 아래에 요약 바 + 게이트 + 두 표 표시. 5개 값 동일 행은 어느 표에도 없음

④ BEFORE 재사용같은 BEFORE 행을 다시 클릭 → 다른 AFTER 행 선택 → 적용두 번째 줄이 추가되고 배지가 사용 2 로 증가 (#18)
⑤ 미등록 매핑BEFORE 의 미등록 행 → AFTER 1행 → 적용변경전 칸이 5칸 합친 미등록 한 줄, 판정 추가
⑥ 게이트AFTER 를 일부만 매핑한 채 다음 STEP 클릭이동 차단 + "AFTER 항목 n건이 아직 매핑되지 않았습니다" 에러. 전부 매핑하면 게이트가 초록으로 바뀌고 이동 가능 (#14)
⑦ 짝 해제변경전/변경후 표에서 ✕ 클릭줄이 사라지고 AFTER 행이 되살아남 + BEFORE 사용 배지 감소, 게이트 다시 빨강

잠재 이슈 · 주의사항

  • 재선택 롤백의 범위 — 스냅샷은 Merge 직전 시점이므로, Merge 이후 사용자가 J/O 를 수동 편집했다면 그 편집도 함께 사라집니다. ConfirmModal 문구에 명시합니다.
  • 임시저장 후 재진입 — 스냅샷을 문서에 저장하지 않으면 재진입 후에는 J/O 롤백이 불가합니다(§7-1 에서 결정).
  • 조리법 변경 시 초기화 — process_id 변경 시 J/O 재조회로 참조 상태가 초기화됩니다(index.tsx:507-510). merge_pairs·스냅샷도 함께 비웁니다.
  • Merge 후 J/O 수동 편집 — 저장되는 merge_pairs 는 Merge 시점 스냅샷 성격입니다. 상세 페이지 카드에도 "Merge 시점 기준" 문구를 답니다.
  • 기존 매칭 키 결함 — computeLayerMerge 키에 layerid 가 빠진 알려진 문제(docs/REQUEST.md:282)는 이번 범위 밖(#8 현행 유지). 새 함수는 process_id+layerid 기준이라 두 계산의 기준이 다릅니다 — 의도된 분리입니다.
  • 구버전 문서 — merge_pairs 없는 문서는 ?? [] 백필, 상세 카드는 빈 배열이면 숨김.
