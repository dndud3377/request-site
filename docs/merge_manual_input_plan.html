데모 사용법 — ① '미등록' 칸을 클릭하면 입력 칸으로 바뀝니다. ② 아래 샘플을 복사해 process_id 칸에 붙여넣기 하면 4열 × N행이 한 번에 들어갑니다. ③ 반대쪽 행 수가 자동으로 맞춰집니다. ④ ↺ 는 그 행을 양쪽 미등록으로 되돌리고, ✕ 는 행을 지웁니다.

표의 상세 규칙

  • 미등록 표시 — 그 쪽 4칸이 모두 비면 5칸을 합쳐 미등록 한 줄로 그립니다(현재 자동 표시와 동일). 클릭하면 입력 칸으로 전환되고 첫 칸에 포커스가 갑니다.
  • 양쪽 모두 미등록인 행 — 판정 뱃지는 미작성, 게이트에서 오류로 잡힙니다(빈 행을 남긴 채 상신 불가).
  • 행 수 동기화(요청 6) — 한 행이 곧 변경전+변경후 한 쌍이라 구조적으로 항상 같습니다. 변경후 3번째 행에 4행을 붙여넣으면 3~6행이 채워지고, 없던 4~6행이 생기며 그 행들의 변경전은 미등록이 됩니다.
  • 붙여넣기 — 클릭한 칸이 아니라 그 쪽 첫 칸(process_id)부터 4칸을 채웁니다. 5열 이상이면 앞 4열만 쓰고, 4열 미만이면 채운 칸만 반영합니다. 행이 모자라면 자동 생성.
  • layer 칸 — 수기로 채운 쪽은 항상 — 이며 입력·붙여넣기 대상이 아닙니다. 참조 요청서에서 자동 생성된 행은 원래 값을 유지합니다.
  • 구분 — 새 행은 J-ayer 로 시작, 드롭다운으로 O-ayer 로 바꿉니다. 자동 생성 행의 구분도 바꿀 수 있습니다.
  • 판정 — 사용자가 고르지 않습니다. 변경전 미등록 → 추가, 변경후 미등록 → 삭제, 양쪽 값 있음 → 변경 로 매 편집마다 재계산합니다.
  • 값 비교 강조(요청 4번) — 양쪽에 값이 있는 행은 변경전·변경후를 컬럼별로 대조해 다른 값을 주황 굵게 표시합니다(기존 .ba-cell-changed 규칙 그대로). 입력·붙여넣기 즉시 갱신되고, 한쪽이 미등록이면 비교 대상이 없으므로 강조하지 않습니다.
  • ✕ 버튼 — 참조 있음 모드에서 자동 생성된 짝을 지우면 기존처럼 BEFORE/AFTER 표로 되돌립니다. 수기로 추가한 행은 그냥 사라집니다.

7. 결정 완료 / 잔여 주의사항

① 버튼 이름 — 결정: 기존 Merge 유지

참조 요청서 옆 버튼은 request.merge_button = "Merge" 그대로, 표 ① 확정 버튼은 request.ba_apply = "적용" 그대로. 이름 충돌이 없으므로 i18n 라벨 변경이 없습니다.

② 상세 페이지 문구 — 결정: 반영

request.ba_detail_note "Merge 시점 기준" → "작성자 편집 반영" (ko/en 동시). 자동 생성 행까지 편집 가능해진 사실과 문구를 일치시킵니다. 동작 변경은 없습니다.

③ '없음' 의 성격 — 결정: 직접입력 모드가 아니라 '없음' 으로 확정되는 값

'없음' 을 고르고 Merge 를 누르면 참조 요청서 = 없음 으로 확정되어 입력란·라디오가 잠기고(참조 문서를 확정했을 때와 같은 취급) 그 결과 표가 열립니다. 화면 어디에도 '직접 입력 모드' 라는 별도 개념을 두지 않습니다 — 표가 편집 가능한 것은 두 모드 공통 성질입니다.

④ 라디오를 '있음 ↔ 없음' 으로 바꿀 때 (잔여 — 다르게 원하시면 알려주세요)

확정 전에는 자유롭게 전환합니다. 확정 후에는 ↻ 재선택 으로만 풀 수 있고, 입력한 표가 사라지므로 기존 재선택과 동일하게 확인 모달로 먼저 경고합니다.

11. 수동 검증 시나리오 (완료 후 제공 예정)

  1. http://localhost:10011 → 의뢰서 작성 → STEP 1 → 기타 목적 Overlay 변경 클릭 → 참조 요청서 블록에 라디오 2개가 보이고 버튼 이름이 적용인지 확인
  2. 참조 요청서 없음 라디오 → 입력란에 없음 이 뜨고 비활성 → Merge → 입력란·라디오가 잠기고 안내 문구가 뜨며 변경전/변경후 표가 미등록 / 미등록 1행으로 열리는지 확인
  3. 변경전 '미등록' 칸 클릭 → 입력 칸 전환 → 엑셀에서 4열 10행 복사 후 붙여넣기 → 10행이 생기고 변경후가 전부 미등록인지, 판정이 전부 추가인지 확인
  4. 변경후 3번째 행 클릭 → 4행짜리 데이터 붙여넣기 → 3~6행이 채워지고 변경전 행 수도 함께 유지·확장되는지 확인 (요청 6번)
  5. 임의 행의 구분 드롭다운을 O-ayer 로 변경 → 뱃지 색이 보라색으로 바뀌는지 확인
  6. 한 행의 변경전·변경후를 둘 다 채우고 SD 만 서로 다르게 입력 → 판정이 변경이 되고 SD 칸만 주황 굵게 강조되는지 확인 (요청 4번)
  7. 값이 든 행의 ↺ 클릭 → 그 행이 양쪽 미등록으로 돌아가고 판정이 미작성이 되는지 확인
  8. 한 행의 SP 만 비운 채 다음 STEP → 해당 칸이 빨갛게 표시되고 상신이 차단되는지 확인 (4칸 필수)
  9. 임시저장 → 목록에서 재진입 → 표·모드·구분이 그대로 복원되는지 확인
  10. 참조 있음 모드로 기존 Merge 를 수행 → 표 ①·② 가 기존대로 동작하고, 표 ② 의 셀을 직접 고칠 수 있는지 확인 (기존 회귀 없음)
  11. 상신 후 상세 페이지 STEP1 카드에서 표가 동일하게 보이는지 확인
