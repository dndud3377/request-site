4.2 Only MAP + 연구소 제품 변경

경로 구조는 그대로이고, RA 인원만 늘어납니다. 백엔드 post_approver_users()가 이미 "고정 1명 + detail.post_approvers"를 합치므로 결재 생성 로직은 수정이 없습니다 — 검증 조건만 넓히면 됩니다.

4.3 MAP 삭제/수정 신규 경로

PL 검토→ 병렬 4단계 (+각 검토자) P → PV 검토자 R → RV 검토자 J O →4단계 전원 합의 시 승인 EEVRA 후결자

상신 절차(지정 PL·검토자·통보처)는 기존과 동일합니다. 결재 현황 화면에서는 현재 O·E 가 병렬로 보이는 것과 같은 방식으로 4개가 나란히 표시됩니다.

이 경로에만 적용되는 예외 — 고정 후결자도 붙지 않습니다.
현재 모든 의뢰서가 settings.POST_APPROVER_LOGINID 고정 후결자 1명을 받습니다 (mailer.py:215 post_approver_users()). MAP 삭제/수정은 이 관례에서 유일하게 벗어나는 경로가 됩니다. 의도된 결정이며, _advance_* 신규 분기에서 RA 생성 자체를 하지 않는 방식으로 구현합니다.
구조상 가장 큰 변경입니다 — 바뀌는 전제 4가지를 근거와 함께 적습니다.
  • R 의 역할이 바뀝니다. 현재 R은 병렬 단계를 여는 관문이고, _advance_to_parallel()이 R 합의 시점에 P/O/E/RA 를 만듭니다(views.py:1205). 새 경로에서는 R 이 병렬 구성원 중 하나가 되므로, PL 합의 직후 4개를 한 번에 생성하는 별도 분기가 필요합니다.
  • J 의 생성 시점이 바뀝니다. 현재 J는 P 가 담당자+검토자까지 완료돼야 _advance_after_p_review()에서 생성됩니다(views.py:1165). 새 경로에서는 처음부터 병렬로 존재해야 합니다.
  • 최종 승인 판정이 바뀝니다. 현재 판정은 "J + O + [E·EV] + RA 전원 합의"(views.py:611)이며 P 는 J 의 선행조건으로만 반영됩니다. 새 경로는 "P + R + J + O 전원 합의"라 별도 판정 분기가 필요합니다.
  • 판정을 트리거하는 지점이 늘어납니다. 신규 발견 승인 판정은 지금 elif agent in ('J','O','E','EV','RA') 분기에서만 돌고, P·PV 합의는 J 생성만 합니다(views.py:605-611). 새 경로에선 P 나 R 이 마지막 합의자가 될 수 있으므로, P·PV·R·RV 합의 시에도 판정이 돌도록 분기를 추가해야 합니다. 이걸 놓치면 네 단계가 다 합의됐는데도 문서가 승인되지 않고 멈춥니다.

4.4 메일·반려 수신자 경로 정의 BE

메일 본문의 '결재 경로' 카드와 반려 수신자 산출은 별도 상수를 씁니다. 새 경로용 세 번째 상수를 추가하지 않으면 메일에 없는 단계(E·RA)가 표시됩니다.
