## 2. 연구소 제품 (Only MAP 전용 + 후결자 필수)

### 2-1. 노출 조건
- [ ] `/request` 진입 → STEP1 요청 목적에서 **`Only MAP`** 클릭
- [ ] 기타 목적 줄: 기존 6개(Layer 추가/삭제 ~ FirstA 변경)는 **회색 비활성**, **`연구소 제품`만 클릭 가능**
- [ ] 요청 목적을 `신규`/`차용`/`신규+차용`/`MAP 삭제/수정`/`기타` 로 바꿔보기 → 이번엔 반대로
  **`연구소 제품`만 회색**, 나머지 6개는 정상 선택 가능

### 2-2. 후결자 필수화
- [ ] `Only MAP` + `연구소 제품` 켠 채로 STEP5 까지 이동 → **상신** 클릭
  → 상신 모달에 **후결자 입력칸**이 나타나는지 확인
- [ ] 후결자를 지정하지 않고 상신 시도 → `"C가문 제품·연구소 제품은 후결자를 1명 이상 지정해주세요."`
  로 차단
- [ ] PL 후결자 1명 지정 후 상신 → 정상 상신됨

### 2-3. 해제 시 정리
- [ ] `연구소 제품` + 후결자 지정된 상태에서 요청 목적을 다른 값으로 변경 시도
  → **확인 모달**(`"다른 요청 목적으로 바꾸면 '연구소 제품' 선택과 지정한 후결자가 해제됩니다..."`)
  → 확인 → `연구소 제품` 선택 해제 + 후결자 목록 비워짐
- [ ] `Only MAP` 은 유지한 채 `연구소 제품`만 다시 꺼도 지정했던 후결자가 함께 초기화되는지 확인

### 2-4. 결재 경로는 변하지 않는다
- [ ] 연구소 제품 문서 상신 → PL 합의 → R 지정·합의 → 결재현황에서
  **`PL → R → 후결자`** 순서 그대로인지 확인(P/J/O/E 는 여전히 생성되지 않음 — 기존 Only MAP 과 동일)
- [ ] 후결자(고정 1명 + 지정 1명) 전원 합의 → `승인` 전환

### 2-5. 진행 중 후결자 제거 가드 (이번에 발견·수정한 버그)
- [ ] 위 문서가 `under_review` 상태일 때, 지정 후결자 1명(고정 제외 유일한 추가 후결자)을
  `remove-post-approver` 로 제거 시도(결재현황 상세 → 후결자 관리 UI)
  → **차단**되어야 함 — 토스트에 다음 문구가 **그대로** 보이는지 확인:
  `"C가문 제품·연구소 제품은 (고정 후결자 외) 후결자를 최소 1명 유지해야 합니다. 변경을 원하시면 1명 추가 후 삭제하시기 바랍니다."`
  → **실패 신호 1**: 제거가 성공하고 고정 후결자만 남는다면 회귀
  → **실패 신호 2**: 제거는 막히지만 토스트에 위 문구 대신 `"처리 중 오류가 발생했습니다."`
  만 보인다면 회귀(서버 메시지를 프론트가 버리던 이전 버그)

## 3. MAP 삭제/수정 (P·R·J·O 병렬 경로)

### 3-1. 요청 목적 선택 시 Step1 잠금 (Only MAP과 동일 동작)
- [ ] STEP1 요청 목적에서 **`MAP 삭제/수정`** 클릭 → (이미 다른 값 선택돼 있었으면 확인 모달 → 확인)
- [ ] 기타 목적 6개 전부 **잠김**(연구소 제품도 잠김 — Only MAP 이 아니므로)
- [ ] 흐름도·Backbone·참조 요청서 블록도 잠기고 초기화됨

### 3-2. StepMap 버튼 6개
- [ ] STEP2 진입 → MAP 요청 목적 버튼이 **`신규(NEW)`/`차용(CLONE)`/`기등록(EXISTING)`/`ADI`/`수정`/`삭제`**
  6개 모두 표시
- [ ] `MAP 삭제/수정` 목적일 때: `수정`/`삭제`만 클릭 가능, 나머지 4개는 회색
- [ ] 다른 요청 목적일 때: 반대로 `수정`/`삭제` 2개가 회색(비활성)

### 3-3. 이유 입력칸 — 하위 블록 숨김 + 에디터
- [ ] `수정` 클릭 → **원본 위치·REV·Only C가문 제품·지도편차·예외구역·X표시(M-shot)·Inter·Map Option
  블록이 전부 사라지고**, "MAP 수정 이유" 라벨의 입력칸만 남는지 확인
- [ ] 입력칸에 텍스트 입력 + **이미지 붙여넣기(Ctrl+V)** → 이미지가 즉시 업로드되어 본문에 삽입되는지 확인
- [ ] **입력칸 높이가 기존(320px) 대비 2배(640px)로 넓어졌는지** 확인
- [ ] 텍스트/이미지를 여러 개 넣어 내용을 길게 만들기 → **입력칸 자체(고정 높이)만 세로 스크롤**되고
  페이지 전체 높이는 늘어나지 않는지 확인
- [ ] 아무것도 입력하지 않고 '다음' 시도 → **필수 오류로 진행 차단**
- [ ] 이미지만 넣고(텍스트 없이) '다음' 시도 → **통과**되는지 확인(텍스트 없어도 이미지만으로 유효 판정)

### 3-4. 수정 ↔ 삭제 전환 + map_type 값
- [ ] `수정` 선택 후 이유를 작성 → `삭제` 버튼 클릭
  → **라벨만 "MAP 삭제 이유"로 바뀌고 작성했던 내용은 그대로 남아있는지** 확인(확인 모달 없음)
- [ ] 다시 `수정`으로 되돌려도 내용 유지되는지 확인
- [ ] 상신 후 문서 목록의 **제목**에 `MAP(수정)` / `MAP(삭제)` 로 한글이 보이는지 확인
  (예전엔 `MAP(EDIT_REQ)`/`MAP(DELETE_REQ)` 처럼 영문 코드가 그대로 보였음 — 회귀 신호)

### 3-5. 상신 및 결재 경로 — 4단계 병렬
- [ ] 이유 작성 후 상신 절차(지정 PL·검토자·통보처 지정)는 기존과 동일하게 진행 → 상신
- [ ] PL 합의 → 결재현황에서 **"현재 단계" 칸에 `(R/J/P/O)` 형태의 배지 1행**이 보이는지 확인
  (개별 행 여러 줄이 아니라 **하나의 행**이어야 함, 순서는 R→J→P→O 고정)
  (E·후결자(RA)는 생성되지 않음 — 배지 문자에도 포함되지 않아야 함)
- [ ] **P를 합의**시키면 배지가 `(R/J/O)` 로 **P 글자만 사라지는지** 확인
  (J 는 P 완료를 기다리지 않고 처음부터 병렬 대기 중이므로, P 합의 전에도 J 는 이미 배지에
  포함돼 있었어야 함 — "P 다음에야 J가 나타남" 은 회귀 신호)
- [ ] **P·J·O 를 먼저 합의**시키고 **R을 마지막에 합의** → R 만 남았을 때 배지가 `(R)` 로 보이는지
  확인 → R 합의 시 `승인`으로 전환
- [ ] 반대로 **R을 먼저 합의**시키고 **P를 마지막에 합의** → 역시 정상적으로 `승인`까지 가는지 확인
  (일반 경로는 P 합의로 승인 판정을 하지 않으므로, 이 케이스가 새로 추가한 판정 분기의 핵심)
- [ ] R 담당자 지정 시 검토자(RV)까지 함께 지정 → 담당자만 합의한 상태에서는 배지에 **`R` 이
  계속 남아있는지**(검토자 합의 전까지 안 지워짐) 확인
- [ ] P 담당자 검토중(claim) 선점 후 합의 시 검토자(PV, `reviewer_loginids`) 함께 지정 →
  검토자 합의 전까지 배지에서 `P` 가 안 지워지는지 확인
- [ ] 네 단계 모두 합의 완료 → 배지가 사라지고 **이름 목록**(`R(이름) / J(이름) / P(이름) / O(이름)`)
  으로 바뀌는지 확인

### 3-6. 결재 상세 화면
- [ ] 상신된 MAP 삭제/수정 문서 상세 → **MAP 정보 섹션**에 이유 카드가 표시되는지 확인
  — **라벨은 수정/삭제 관계없이 항상 "MAP 수정 이유" 하나로 고정**되는지(요청 반영, 작성 화면과
  다름) 확인
- [ ] 이유 카드 표시 칸의 **최대 높이가 기존(420px) 대비 2배(840px)로 넓어졌는지** 확인
- [ ] **'결재 경로' 탭**에서 **후결자(RA) 행**이 `대기`가 아니라 **`해당없음`**으로 표시되는지 확인
  (승인 전/후 모두)
- [ ] E(MASK) 행도 `해당없음`으로 표시되는지 확인(J-layer 가 비어 있어 plel 판정 자체가 없음)
- [ ] MAP 요청 목적 Chip 값이 `수정`/`삭제` 로 한글로 보이는지 확인(영문 코드 노출 없음)

### 3-7. 반려
- [ ] P·R·J·O 중 아무 단계에서나 반려 → 문서 전체가 `rejected` 로 전환되는지 확인(기존 규칙과 동일)
- [ ] 재상신 시 새 회차로 PL 검토부터 다시 시작하는지 확인

## 4. 회귀 확인 (기존 경로가 그대로인지)

- [ ] **일반 문서**(`신규` 등) 상신 → PL 합의 → R 지정만 하고 아직 합의 전 상태에서 결재현황 확인
  → `(R/J/P/O)` 식 배지가 **나타나지 않고**, 기존처럼 "RFG" 단일 텍스트로 R단계가 순차 표시되는지 확인
- [ ] 일반 문서에서 R 합의 후 P/O 병렬 진입 → 이 시점에도 **배지가 아니라 기존처럼 경로1(P/J)·
  경로2(O) 여러 줄**로 표시되는지 확인(문서마다 줄 수가 다름 — MAP 삭제/수정만 한 줄 배지)
- [ ] **Only MAP** 문서(연구소 제품 없이) → 기존과 동일하게 `PL→R→후결자`, 결재현황·상세 모두
  변경 전과 동일하게 보이는지 확인
- [ ] **C가문**(`only_prodc=Yes`) 문서 → 후결자 필수·제거 가드 기존 규칙 그대로인지 확인
  (연구소 제품 관련 변경이 C가문 로직을 건드리지 않았는지)
- [ ] 기존 `ADI CD 변경` 목적 문서 작성 → StepMap 의 `ADI` 버튼 잠금 동작(표시 전용) 그대로인지 확인
  (map_type 버튼이 4개에서 6개로 늘어난 것이 ADI 로직에 영향 없는지)
